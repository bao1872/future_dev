# M7 深亏区指标口径审计

## 矛盾来源：报告中的列误读，不是指标定义冲突

M7 报告曾同时出现：

- 深亏区表：`预测EXIT组真实值 = −0.0346`（负）
- 正文：2.5R 预测 EXIT 组真实增益约 `+0.767R`（正）

**结论：二者并非同一统计量的矛盾，而是正文把「召回率」误读成了「R 值」。**

`m7_deeploss.csv` 的实际列顺序为：

```
目标,视图,目标类型,模型,状态数,真实EXIT有利比例,AUC,准确率,
正类精确率,正类召回率,负类精确率,负类召回率,
预测EXIT组真实值,预测HOLD组真实值
```

2.5R / S0_CURRENT / LightGBM 一行的实际取值：

| 字段 | 值 |
|---|---:|
| 真实EXIT有利比例 | 0.8418 |
| AUC | 0.5184 |
| 准确率 | 0.3628 |
| EXIT_precision | 0.8717 |
| EXIT_recall | 0.2890 |
| HOLD_precision | 0.1646 |
| **HOLD_recall** | **0.7670** ← 被正文误读为 +0.767R |
| 预测EXIT组真实值 | **−0.034627** |
| 预测HOLD组真实值 | **−0.111999** |

即 `0.767` 是 **HOLD 类召回率**，不是收益。表本身自洽：
预测 EXIT 组 −0.035R，预测 HOLD 组 −0.112R，两组均为负。

## 为什么 85% 有利但均值仍为负

用轨迹直接重算（不重新训练），深亏决策状态 `current_unrealized_R < -0.75`：

| 目标 | 状态数 | EXIT有利比例 | **均值** | **中位数** | p10 | p90 | 正增益笔数/均值 | 负增益笔数/均值 |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| 1.5R | 3351 | 85.56% | **−0.0584** | **+0.1383** | −0.846 | +0.231 | 2867 / +0.170 | 484 / −1.411 |
| 2.0R | 3533 | 85.51% | **−0.0659** | **+0.1385** | −0.756 | +0.231 | 3021 / +0.169 | 512 / −1.453 |
| 2.5R | 3579 | 85.39% | **−0.0682** | **+0.1385** | −0.761 | +0.231 | 3056 / +0.169 | 523 / −1.457 |

**中位数 +0.139R、85% 的状态提前退出更好，但均值被 15% 的「后来修复并打到止盈」状态拉负**
（那些状态提前退出平均损失 −1.46R）。

这正是 M5「浮亏退出平均负贡献」的精确机制：
不是退出没有价值，而是**均值被右尾修复交易所主导**。
因此这是一个尾部风险权衡问题，不是均值预测问题——也解释了为什么
AUC≈0.5 的模型无法在此取胜。

## 采用的统一口径（今后只使用这些名称）

- `state_weighted_exit_gain_R__pred_EXIT` / `..._pred_HOLD`
  状态级等权（每个决策状态权重相同），跨折直接拼状态，字段
  `exit_gain_vs_fixed_R`，**非 first-exit-only**。
- `state_share_exit_gain_positive`：状态级 EXIT 有利比例。
- `state_weighted_mean_exit_gain_R` / `state_median_exit_gain_R`：
  状态级均值与中位数（二者必须并列报告）。
- `HOLD_recall` / `EXIT_recall`：分类召回率，是比率不是收益。

重命名后的表见 `m7_deeploss_renamed.csv`；
分布审计见 `m7_deeploss_distribution.csv`。

## 对总体结论的影响

**无影响。** 暂停强化学习/动态退出的裁决依据是
AUC≈0.5、深亏区 AUC 未改善（S0 0.518 → S2 0.507）、
回放跨折不稳（F3 崩塌），以上均不涉及被误读的那一列。
